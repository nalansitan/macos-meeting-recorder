# 使用与技术说明

仅面向本机 Apple Silicon Mac（macOS 15+）。SwiftUI 原生窗口使用 ScreenCaptureKit
分别采集麦克风和系统播放音频，不需要虚拟声卡，不保存屏幕图像。
录音主体使用 Swift / SwiftUI，导出由 Python 和 FFmpeg 完成。
macOS 26+ 默认开启 SpeechTranscriber 离线实时字幕，分别标记“我 / 会议对方”，结束后自动保存同名 SRT。
macOS 15 可关闭字幕后仅录音。

应用图标原图位于 `Resources/AppIcon.png`，采用蓝色圆角底板、对话气泡、双组波形及字幕短线。
使用内置图像生成工具设计，完整提示词见 `Resources/AppIcon-prompt.txt`。
构建脚本自动生成 16–1024 像素的标准/Retina 图标，打包为应用资源中的 `AppIcon.icns`，
并用于 Finder、Dock 和窗口内的品牌标识。

## 安装到应用程序目录

在仓库根目录执行以下命令，构建后安装到 `/Applications/会议录音.app`：

```sh
bash scripts/build.sh
ditto "build/会议录音.app" "/Applications/会议录音.app"
codesign --verify --deep --strict "/Applications/会议录音.app"
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f "/Applications/会议录音.app"
mdimport "/Applications/会议录音.app"
open "/Applications/会议录音.app"
```

如果复制时提示没有权限，只将上面的复制命令改为
`sudo ditto "build/会议录音.app" "/Applications/会议录音.app"`，并按系统提示输入管理员密码。
构建命令无需 sudo。

之后可以在 Finder 的“应用程序”中打开，或按 `⌘ Space` 搜索“会议录音”；
Spotlight 索引可能需要片刻。如果暂时搜不到，可先从“应用程序”打开一次，
并检查 Spotlight 是否排除了“应用程序”目录。命令行也可用 `open -a "会议录音"` 启动。
安装的是完整应用副本，日常启动不需要再定位仓库内的构建路径。

### 更新与卸载

更新前先结束录音、等待导出完成，再退出“会议录音”；随后重新执行上述构建、复制和注册命令，
最后从 `/Applications` 打开新版本。只运行构建命令不会更新已安装的副本。
已有录音位于所选保存位置（默认 `~/Movies/会议录音/`），更新应用不会修改它们或重置保存位置。
卸载时将“应用程序”中的“会议录音”移到废纸篓即可，录音文件仍保留。

依赖本机 Xcode Command Line Tools、系统 Python 3 与 FFmpeg（支持 `/opt/homebrew/bin/ffmpeg`）。
应用在仓库内构建并本地签名，不安装系统服务、不自动开始录音。
首次点击“开始录音”时，需要在 macOS 中允许麦克风及屏幕与系统音频录制权限；
若拒绝，请前往系统设置 → 隐私与安全性调整权限，退出后重新打开应用。
本地临时签名在重新构建后可能需要重新授权。

## 使用

1. 选择麦克风，开始录音；两路音量条用于确认自己与对方的声音都有输入。
2. 系统音轨采集本机其他应用的播放声音（包括通知声音），当前不限定某一个会议应用。
   建议使用耳机，防止扬声器的声音又被麦克风录入。也可在录音前开启“软件回声消除（实验性）”。
3. 可暂停、继续；暂停期间停止计时并丢弃两路采样。继续后接续暂停前的录音时间，导出不包含暂停时段的静音；在暂停状态结束也不会计入暂停时间。
   每路音量条旁有“暂停此路 / 继续此路”，可单独停止保存麦克风或电脑声音。单路暂停不停止计时，
   该路的空缺在混音时保持静音，另一条正常录制；两路分别暂停也不停止计时，需要停表请使用整体“暂停录音”。
   整体暂停/继续不会重置各路的暂停状态。这是应用内丢弃该路采样，不会修改系统麦克风权限或会议软件静音设置。
4. 结束并保存后自动生成一个单条混合音轨的 `meeting.m4a`。历史或中断录音可从“历史录音”打开后保存。导出不调用模型，原始片段保留用于恢复。
   结束后等待“已自动保存”及文件路径出现即可，不需要再点一次按钮；长录音混音可能需要几分钟。
   采集停止异常时仍会尝试导出已保存片段，失败时显示原因；失败时可点击“重试保存”，历史录音可再次“保存录音”。
   离开未完成录音时可选择保存、保留草稿或取消；保存失败会留在当前录音中显示错误。导出进程的结果保存在录音目录的 `export.log`。
5. 开启实时字幕时，结束后自动生成与 M4A 同名的 SRT，无需上传或再次识别。
   如需重新识别、翻译等处理，可自行将导出的 M4A / SRT 导入其他工具。应用不会自动上传文件。

### 应用内回听（0.7.0）

“播放录音”打开应用内的回听面板并开始播放，不再跳到系统默认播放器的黑色视频窗口。
上方使用默认 26 点的当前字幕，可调整为 20–36 点；下方显示带时间戳的完整字幕并高亮正在播放的句子。
点击任一句字幕可跳转，支持拖动进度条、前后跳 10 秒、0.75–2 倍速，空格暂停/继续，左右箭头跳转。
手动滚动字幕时暂停跟随，可用“跟随播放”开关重新定位当前句；“完成”或 Esc 关闭面板并停止声音。
优先读取音频旁的同名 SRT；旧录音缺少 SRT 时读取已确认的字幕记录。没有字幕或字幕读取失败时仍可回听音频。
历史列表 → “打开 / 改名” → “播放录音”也使用同一回听面板。已有音频和字幕文件不会被改写。

播放自动化验证（只生成并播放静音测试文件，不采集麦克风）：

```sh
bash scripts/test-playback.sh
```

### 录音状态、草稿与历史记录

- 顶部显示准备录音、录音中、已暂停、正在保存、草稿待保存、保存失败或已保存。
  音频成功而字幕失败或不完整时显示“音频已保存 · 字幕异常”，不会把音频误报为未保存；可重试生成字幕。
- “新建录音”回到录音准备页，不会自动开始采集。新一场清空名称、字幕和计时，保留设备、语言和保存位置偏好。
- 新建、切换历史录音、关闭窗口和退出应用共用处理规则：已经保存时直接继续；
  录音中、草稿、保存失败或修改名称后，提供“保存并继续 / 取消 / 保留草稿并继续”。
  保存失败不离开当前录音；保留草稿会结束当前采集，但不生成成品音频，之后可从记录中恢复保存，不能追加录制。
  取消文件夹选择不会切换当前录音。保存或模型下载期间禁止切换，退出时会显示处理中的提示。
- “历史录音”列出当前、默认及曾经使用过的保存位置中的录音，显示名称、日期、时长和状态。
  保存期间仍可浏览列表；打开、改名和删除操作需等保存完成。“打开 / 改名”进入录音后，可修改顶部名称并保存。
  旧版本使用的其他位置可通过“从文件夹打开…”加入。外置磁盘未连接时，该位置的录音暂不显示。
  重启发现未完成录音时打开记录列表，可恢复、移到废纸篓，或点击“完成”稍后处理。
- 录音中的“更多 → 放弃本次录音…”以及历史录音的“移到废纸篓…”都会确认后处理整场目录，
  包含所有音频成品、字幕和原始片段；可在 Finder 废纸篓中恢复。移动失败时保留当前记录并说明原因。
  操作前检查采集和导出锁，其他进程正在使用的录音不可移除。
- `recording-note.json` 原子保存会议名称和草稿/保存状态。已有录音不要求此文件，按原有清单与导出结果识别状态。
  旧录音已导出但在 Finder 中改过音频文件名时，若目录内只有一个非空 M4A，会自动识别已有成品；
  多个候选、缺少导出记录或中断录音不会猜测完成状态。识别不会改名或重写旧录音文件。
  原始音频仍实时写盘，草稿不等于文件尚未写盘；意外中断仍受下文的恢复边界限制。

### 实时说话人与跨录音姓名（0.9.0）

在“设置 → 说话人识别与姓名”中点击“从 Hugging Face 下载模型”，完成后开启实时区分。
设置会显示模型完整保存路径，可点击“打开模型目录”在 Finder 查看。也可通过“手动下载模型”链接获取文件，
解压后点击“导入本地模型…”，选择同时包含 `pyannote_segmentation.mlmodelc` 和 `wespeaker_v2.mlmodelc` 的文件夹
（也支持它们的 `speaker-diarization` / `speaker-diarization-coreml` 父目录）。应用先复制到临时目录并用 Core ML 验证，
成功后替换模型并重新计算版本指纹；导入失败保留原模型，人员库不被导入覆盖。录音或处理时禁止导入。

录音中点击字幕栏的“标注说话人”，可为我方/会议方各自的说话人命名，或关联已记住的人员。
勾选“记住此人的声纹”后，其他录音会自动匹配姓名。自动匹配不更新人员库；只有人工确认才登记样本。
声纹不足时可取消勾选，仅标注本场。系统音轨包含其他应用声音，因此播放视频中的人声也可能进入会议方。

- 保留现有苹果双路实时转写。说话人模型每路按 4 秒非重叠窗口后台分析；字幕先显示音源，之后补充姓名/编号。
- 两路共用一套 Core ML 模型、各自维护聚类，串行运行于 utility 队列，使用 CPU + Neural Engine 配置。
- 输入最多排队 8 秒音频且最多 256 个回调包；每包上限 2 秒。繁忙时跳过人物分析并提示，不阻塞录音与转写。
- 静音不运行人物模型；每路最多 64 个聚类，内存只保留最近 2000 条人物时间段，完整时间段追加到磁盘。
- 只有至少 1.5 秒、无明显重叠的发言才用作登记候选；累计至少 3 秒才允许持久登记。每个人最多保留 5 个手工确认样本。
- 人员库不区分我方/会议方，同一人换音轨仍可匹配。未知、相近声纹或多说话人混合字幕不强行命名。
- 跨会议姓名使用连续至少 3 次分析、累计至少 6 秒的清晰语音确认；每次相似度需达到 0.55，且领先第二候选至少 0.12。同一批分段只计一次证据，不再用单个最长片段的 0.80 门槛判断。证据不足或出现歧义时回退编号，人工确认的姓名不被覆盖。该门槛仍需更多真实会议校准；历史录音不会自动回填。
- 新字幕保留识别器的文字片段时间戳，实时显示、回听和 SRT 导出按说话人变化拆行；人物分析稍晚返回时自动重新分段。单个文字片段跨越多人时显示“多人/待确认”。
- 历史字幕没有细分时间戳时保留原文，涉及多人的整行显示“多人/待确认”，不按发言时长强行归给一个人。拆行不修改原始字幕或已保存的姓名标注。
- 回听优先读取最新人员标注，已经导出的 SRT 点击“保存录音”重新生成。历史录音可以继续标注已保存的人物；没有人物时间段的旧录音暂不补跑模型。
- 人员库与模型保存在 `~/Library/Application Support/MeetingRecorder/Speakers/`；录音目录保存 `speakers.json` 与 `speaker-turns.jsonl`。
- 模型下载失败可重试；录音开始只加载本地文件，不触发下载。模型资产指纹隔离不同版本的声纹，换模型后需重新登记。
- “设置”支持删除持久声纹，历史录音中已经保存的姓名仍保留。声纹和姓名不上传、不经 iCloud 同步代码传输。

首次构建需要 Swift 6.2+ 和网络，SwiftPM 将 FluidAudio 固定到 `Package.resolved` 中的提交；不启用其 TTS 等可选特性。
模型在用户点击下载时从 Hugging Face 获取。模型本身缓存为固定的本地资产，日常运行不会自动升级。
第三方说明与 SDK 许可证打包在应用 Resources 中。

0.9.0 的历史合成语音测量（M5 Pro / 48 GB，不能作为 0.9.2 占用数据）：每路含两种声音，双路各约 20.9 秒，随后在新录音中再次输入并识别已标注声纹。
两轮共约 43.7 秒墙钟时间，CPU 时间约 1.78 秒，测试进程最大常驻内存约 156 MiB；不包含苹果转写和 AEC，
不是完整应用的占用或准确率保证。已验证无麦克风采集的双路分组、跨录音身份复用和本地模型加载。
说话人识别仍需真实会议验收，尤其是相似声音、外放残留回声、短插话、多人同时讲话和长会议。
4 秒是窗口长度，不保证每句在 4 秒内完成身份确认；录音开头、模型首次推理和短句可能延迟或保持待识别。

验证（不采集麦克风/系统声音）：

```sh

python3 -m unittest discover -s tests -p 'test_*.py'
```

可选真实模型测试使用 `SPEAKER_MODEL_TEST_ROOT` 指定独立测试目录，目录需有 `fixture.aiff`，
其中包含至少两种各自连续发言数秒的声音。运行 `build/speakers-test` 会下载测试模型到该目录，

### 软件回声消除（0.8.0，实验性）

录音前在“设置 → 声音与回声消除”中开启“软件回声消除（实验性）”。默认关闭，手动选择后会记住；
录音及处理期间不能切换。支持在应用内选择麦克风。
2026-10-28 用户已按飞书单机会议及字幕流程试用，确认本机内置麦克风和外放下的问题已解决；
其他设备、长会议及远端实际听感仍需分别验证。

0.8.0 已移除 `AVAudioEngine` / VoiceProcessingIO 采集路径。麦克风和系统播放声音都由
ScreenCaptureKit 普通采集，WebRTC Audio Processing / AEC3 只在本应用内处理 PCM。
不创建播放引擎，不修改默认设备、系统音量、硬件增益或设备采样率；不引入虚拟声卡。
关闭模拟/数字自动增益控制和额外降噪，优先验证消回声与本地人声保留。
处理后的麦克风用于分路 CAF、最终混音和实时字幕；系统音轨保持原样。

两路按 host clock 对齐到 48 kHz 单声道、10 ms 帧，容忍约 150 ms 的回调先后差异；
加上处理帧缓冲，字幕额外延迟约 160 ms。对固定版本算法的约 9 ms 延迟做了补偿，
停止、整体暂停和麦克风单路暂停时排空尾部；整体暂停后重置算法以免跨暂停串音。
时间戳用于持续对齐；时钟漂移、格式变化、长会议和真实外放非线性仍需现场验证。
暂停保存电脑声音不会中断 AEC 参考流。未收到参考帧时保留原麦克风声音，避免误删本地发言；
因此缺参考期间可能保留回声。异常时间戳、格式转换或处理失败会报错并保留已录片段。
缓冲区有固定上限，长时间断流重置适应状态，不累积整场 PCM。

`meeting.json` 使用 `microphoneProcessing: "webrtcAEC3"` 标记新模式；
`echoReferenceMissingFrames` 记录缺参考而保留原声的 10 ms 帧数量（电脑未播放时也可能增加）。
旧录音的 `systemVoiceProcessing` 标记仍可读取，不改写历史音频。

首次构建需要 `uv` 和网络，脚本将固定版本 `webrtc-audio-processing 2.1`、Abseil 20240722.0
及构建工具下载到忽略的 `build/aec-deps/`；主源码 SHA-256 和 Abseil wrap 校验均固定。
仅使用 WebRTC 音频处理模块，不链接音频设备模块。库及所有运行依赖打包为应用内
`Contents/Frameworks/libMeetingAEC.dylib`，安装后不依赖 Homebrew、Python 或网络进行 AEC。
第三方许可证保存在 `Contents/Resources/AEC-Licenses/`。

离线自动化（生成合成 PCM、写入临时文件，不打开麦克风或播放声音）：

```sh
bash scripts/test-software-aec.sh
```

测试涵盖：模拟声学延迟和反射的回声降低、本地独白、双方同时讲话、算法延迟补偿、
变长包与回调顺序、尾部不足一帧、参考缺失、暂停/恢复、暂停电脑声音时仍消回声、
44.1 kHz 双声道重采样、CAF/清单落盘及异常时间戳。合成数据的指标不代表真实会议效果。

飞书单机会议验收：

1. 先只开飞书会议和字幕，使用内置麦克风、内置扬声器，朗读固定一句话，确认飞书字幕正常。
2. 新建本应用录音，开启软件回声消除和实时字幕，朗读同一句，确认飞书字幕仍正常，本应用“我”也有字幕。
3. 播放一段本机测试语音，检查本应用“会议对方”有字，而“我”轨的重复收音减少。
4. 边播放边说另一段话，确认飞书仍能识别你，本应用也能保留你的发言。
5. 结束保存后回听，确认双方声音、最后一句尾音和字幕时间都正常。

飞书单机字幕可检查飞书输入链路，不能代替远端实际听感；最终仍需第二个客户端或真人确认。
测试期间如果飞书收音异常，应结束并保存本应用录音，保留测试结果后分析。

#### 旧系统 AEC 冲突的排查证据

2026-10-28 本机用户对照确认：飞书搭配内置麦克风和外放时，旧模式开启导致对方听不到，关闭后恢复。
触发入口是原来的 `setVoiceProcessingEnabled(true)`。
[Mozilla 1910888](https://bugzilla.mozilla.org/show_bug.cgi?id=1910888#c5) 和
[cubeb-coreaudio-rs #239](https://github.com/mozilla/cubeb-coreaudio-rs/issues/239)
记录过 VPIO 使普通采集路径暴露额外麦克风阵列通道、音量极低，而处理后路径正常的跨进程现象。
这与本机症状高度吻合，但没有直接测量飞书内部采集后端和设备通道变化。
系统 SDK 也明确语音处理必须连接音频设备，不能用 manual rendering 隔离；bypass 不等于释放 VPIO。

旧 `build/aec-validation-2026-10-26/summary.json` 的约 22 dB 下降混入了系统 ducking、降噪和增益变化，
未覆盖第二个采集客户端，不能视为纯回声降低或飞书兼容性的证明。
新实现使用 [WebRTC PCM 接口](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h)
从结构上避开该触发条件；本机飞书单机会议试用已由用户确认问题解决。

### 离线实时字幕

- 主界面以字幕为中心，新窗口默认内容区 860 × 780 点，最小 680 × 560 点，可自由放大。
  顶部只显示会议名称、状态、计时和新建 / 记录 / 设置；两路音量与单路暂停压缩为一行，底部录音操作固定可见。
  设备、回声消除、字幕语言与模型管理、保存位置统一移入“设置”弹出面板（也可按 ⌘,）。
  录音 / 处理期间仍可查看设置，采集配置锁定并显示原因。模型缺失、启动配置失败时可从主界面直接定位设置项。
  状态区只显示简短消息，“详情”可查看完整导出结果和错误。字幕关闭时仍保留大面积占位区与设置入口。
  字幕默认 16 点，在字幕区域可用“字幕字号”滑块调整为 12–36 点，录音时也可调整。
  字号设置会在重启后保留；“恢复默认”恢复为 16 点。字号只影响显示，不修改 SRT 内容。
- 需要 macOS 26+ 和已安装的对应语言模型。默认普通话（简体），也可选择繁体中文、英语或粤语；
  两路使用同一识别语言，不自动判断或切换语言。
- 选择语言后自动检查本机模型，已安装时显示“已就绪”，仅未安装且受支持的语言显示“下载离线模型”按钮。
  点击按钮后通过 Apple 系统服务联网下载并显示进度，完成后重新检查安装状态，隐藏下载按钮。
  已安装模型不会重复下载；下载失败可重试或点击“刷新状态”。打开应用、切换语言或回到应用时会更新状态。
  下载期间禁止开始录音、切换语言和退出；录音期间禁止发起下载。
- 识别只使用 `SpeechAnalyzer + SpeechTranscriber` 的端侧模型，不调用旧的 `SFSpeechRecognizer`、
  网络识别接口。录音启动时先检查 `installedLocales`，预留本地模型资源，
  再检查 `AssetInventory.status == .installed`；模型缺失或不可用时拒绝开启字幕录音，不回退到云端。
  模型下载仅由录音前的手动按钮触发，录音与识别不需要互联网。
  系统可能在下载失败后自行重试，模型的后台维护和更新由 macOS 管理。
- 麦克风标记为“我”，系统播放声音标记为“会议对方”。这是音源标记，不是声纹识别；
  同屋多人共用麦克风、多人会议的远端声音不能逐人区分。佩戴耳机以避免声音串入麦克风。
- 窗口保留最近 300 条已确认字幕和两路临时字幕；临时结果会修订，SRT 只使用已确认文字。
  临时字幕明确标注“识别中”，8 秒没有文字变化后从界面隐藏，重复返回同一文本不会延长显示。
  两路使用系统 `SpeechDetector` 的中等灵敏度检测语音，减少静音和背景噪声的误识别；
  检测只影响字幕，不裁剪原始录音。低音量和远距离语音的识别仍需实际验收。
  界面最多每秒刷新 4 次；逐行按需排版，计时与音量更新不会重新构建整块字幕。
  全部最终文字逐条保存到 `captions.jsonl`，异常退出后可重新导出已落盘的部分。
  主界面显示最近 300 条的保留边界；上翻回看暂停跟随新字幕，可点击“回到最新”恢复。
- 字幕与录音共用时间轴：整体暂停压缩时间，单路暂停保留该路空白；双方重叠讲话在同一字幕条目中显示两行。
  按识别时间片尽量分成 42 字或 6 秒以内的字幕，不伪造单字时间戳。
- “结束并保存”先等待两路最后的识别结果，再导出音频与同名 SRT。
  识别失败、缓冲区溢出或等待最终结果超过 30 秒时会显示提示，录音仍保存；导出会明确警告字幕不完整。
  两路同时收尾，共用约 30 秒的等待窗口；超时后不再等待系统识别服务响应取消，直接保存已确认文字。
  后续迟到的识别结果不会再写入本场字幕。此时限仅限字幕收尾，音频混音另需时间。
  没有确认文字时生成空 SRT 并提示；字幕导出失败不阻止音频保存。
- 历史录音重命名、重新导出时，会用原有字幕记录生成新的同名 SRT，不再次识别。
  未启用字幕或旧版本录音没有字幕记录时，只导出音频。

### 会议命名

窗口顶部的“会议名称”可在录音前、录音中或暂停时填写和修改，例如“项目周会”。
点击“结束并保存”后，自动生成 `<所选父目录>/会议录音/<日期时间-随机编号>/项目周会_<开始日期时间>.m4a`。
例如 `项目周会_2026-10-23_14-30-00.m4a`，主题在前、录音开始时间在后（不是导出时间）。重新导出沿用原开始时间。
每场会议有独立目录，同名会议不会互相覆盖；留空仍保存为 `meeting.m4a`。
文件名中的斜杠等不适合路径的字符会替换为下划线，过长名称会截短。

也可从“历史录音”打开历史录音，修改名称后点击“保存录音”，生成新名称的文件。
已有导出不会因改名自动删除；名称记录在 `export.json` 中，下次打开历史录音会自动填入。
命令行可用 `export.py <录音目录> --title "项目周会"` 命名；省略 `--title` 沿用上次导出名称。

### 设置录音保存位置

在“设置 → 录音保存位置”中点击“更改位置…”，选择一个**父目录**。
应用会自动在其中创建 `会议录音` 文件夹，并在重启后记住此设置。例如选择 `/Volumes/资料/工作` 后：

```text
/Volumes/资料/工作/会议录音/<日期时间-随机编号>/meeting.m4a
```

不需要预先创建或选中“会议录音”子目录。点击“恢复默认”可切回 `~/Movies/会议录音/`。
设置仅影响之后的新录音，不会移动已有文件；已有录音仍可通过“打开历史录音”选择。
正在录音、暂停或导出期间不能更改保存位置。自定义目录或外置磁盘不可用时会提示错误，
不会悄悄切换到其他位置。选择受 macOS 保护的目录时，可能需要按系统提示允许文件夹访问。

每场录音位于 `<所选父目录>/会议录音/<日期时间-随机编号>/`（默认父目录是 `~/Movies`）：

| 文件 | 用途 |
| --- | --- |
| `meeting.json` | 状态、各片段时间戳、音轨与持续时间，每秒检查点 |
| `microphone-*.caf` | 麦克风原始采样，约每 30 秒轮换，格式变化或时间戳断开也会轮换 |
| `system-*.caf` | 系统音频原始采样，同上 |
| `meeting.m4a` | 一个文件、一条混合 ALAC 音轨，16 kHz 单声道，同时包含麦克风与会议声音 |
| `<与音频同名>.srt` | 带“我 / 会议对方”标签的字幕；双方同时讲话时显示两行 |
| `captions.jsonl` | 两路已确认的字幕文字与录音时间戳，可用于重新导出 |
| `captions-status.json` | 识别语言、完成状态和错误；中断录音只恢复已确认部分 |
| `export.json` | 导出时长、音轨数据量与恢复警告 |

导出按每个片段的时间戳补齐静音，不把晚开始的声音挪到零点。随后将麦克风与系统音频
按各 50% 增益混入同一条音轨，避免双方同时讲话时相加削波。普通播放器可直接播放双方声音，
其他转写工具选择默认第 1 音轨即可处理完整会议，无需另导出转写文件。

原始采样率的分路 CAF 片段仍保留用于中断恢复。未命名录音导出 `meeting.m4a`，开启字幕时另导出 `meeting.srt`；
旧版本已生成的文件不自动迁移或删除，打开历史录音并重新保存可将对应 M4A 更新为混合音轨。
ALAC 对对齐并混合后的 16 kHz PCM 无损编码；成品不再保留独立的麦克风与系统音轨。

## 恢复与边界

关闭窗口或退出应用时，未完成录音需选择保存、保留草稿或取消；录音期间阻止系统空闲休眠，但不保证合盖、强制休眠或设备断开后持续录音。
磁盘低于 512 MiB 时停止录音。导出会检查空间，支持最多 8 小时。
实时采集写盘，内存不累积整场音频。

异常退出后，应用会在“历史录音”中提示未完成录音，可打开后恢复保存；也可用“从文件夹打开…”选择未被列出的旧录音。仅已落盘片段可恢复；

## 外放回声消除实验（2026-10-26）

**历史测试：该系统 AEC 路径已在 0.8.0 移除，下列工具会触发旧的系统音频模式，不能在会议进行中运行。**

以下是接入 0.5.0 实验性开关之前的独立验证。已在本机 MacBook Pro 内置麦克风与内置扬声器上完成短时实验，
实验工具不修改正式应用、不上传录音、不下载模型。播放由独立 `afplay` 进程完成，用于模拟其他应用外放。

- 系统 `AVAudioEngine` voice processing 可运行，但必须显式配置两端一致的单声道 / 48 kHz 客户端格式，
  避免输入、输出格式不匹配的 `-10875` 初始化失败及误采集聚合设备的 9 个硬件通道。
- 同一固定测试语音：普通采集的离线模型输出 4 条“我”字幕，处理后输出 0 条；两次识别均正常完成、无错误。
  播放时段录音 RMS 从约 -30.89 dBFS 降至 -53.05 dBFS，相差约 22.16 dB。
  该差值包含系统 ducking、降噪及采集增益变化，不能当作单独回声消除算法的 ERLE 指标。
- 追加朗读测试中，用户确认只在最后的同时外放阶段朗读；前两轮没有本人语音，不能用于保真对照。
  最后一轮处理后识别到“我是本机测试人员，今天下午三点检查服务器”，未识别出固定外放语句；
  这只表明该短片段的人声仍可识别，不代表完整句子、重叠讲话保真已验收。
- 结论：值得继续集成验证，这仍是有限范围的实验验证。仍需完整的人声单讲对照、双讲保真、
  与正式 ScreenCaptureKit 双路时间轴配合、输出音量影响、长会议和设备切换测试。
